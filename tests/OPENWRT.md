# Обязательная проверка перед выпуском

Эти проверки требуют отдельного тестового роутера/VM OpenWrt, а не рабочего домашнего роутера.

1. Собрать IPK/APK в SDK целевого релиза; подписать APK доверенным ключом. Выполнить `ucode -c /usr/lib/nimarkoflow/public.uc` для проверки синтаксиса и фактический вызов RPC. Установить локальные пакеты install.sh. Проверить отсутствие старого маршрутизирующего приложения.
2. Создать учётную запись rpcd только с read/write nimarkoflow-user. Получить её session ID через `session.login`. Вызвать `nimarkoflow.status` — разрешённые scalar-поля, без UCI и метаданных серверов. Проверить через HTTP ubus-сессию, а не `ubus call` от root, что запрещены `uci.get nimarkoflow`, `file.read /etc/config/nimarkoflow`, `file.read /etc/sing-box/config.json`, `file.exec /usr/bin/nimarkoflow`, `file.exec /bin/sh`, чтение subscription-cache и журналов. Проверить также запрет чтения и изменения других UCI-пакетов и отсутствие прав `*`/superuser в `session.access`.
3. Ввести тестовую HTTPS-подписку с HWID. На контролируемом тестовом HTTPS-сервере проверить фактические заголовки `User-Agent: Happ/5.7.0/ios/2609021014549 NimarkoFlow/0.1.0`, `X-HWID`, стабильность HWID после перезапуска и отсутствие fallback на другой User-Agent. Провайдерский URL/ключи не должны появляться в ответах status/import, UI, адресной строке, clipboard, localStorage или sessionStorage. Сам запрос import содержит введённый пользователем секрет — это необходимо для сохранения.
4. Проверить действительную загрузку VLESS и HY2, отказ провайдера по HWID, истечение подписки, неверный User-Agent, недоступный DNS и HTTPS. Проверить обновление кнопкой и по расписанию. Проверить маршрутизацию full/selective и восстановление DNS/маршрутов при остановке. Для XHTTP использовать поддерживающий его движок.
5. Проверить `stat`: /etc/config/nimarkoflow — 0600, закрытые runtime/cache-каталоги и файлы. Проверить новый sing-box config после генерации и cron-обновления, что секретные файлы закрыты. Проверить `ss -lntp`, что порт 9090 доступен только на loopback и недоступен из LAN/WAN.
6. Проверить параллельные import/refresh/remove, отказ диска, принудительное завершение RPC, отсутствие зависших фоновых операций, корректность lock recovery. Удаление профиля не является гарантированным стиранием памяти/flash и старых backup/cache.
7. Проверить интерфейс в реальных LuCI темах на ширинах 390/768/1280, клавиатурное управление, модальное удаление, пустое состояние, недоступный backend и реальный reconnect. Проверить обновление пакета и сохранность закрытой конфигурации.

Абсолютная защита от root не является критерием приёмки: для этого нужен другой дизайн продукта и серверное ограничение повторного использования полученных ключей.
